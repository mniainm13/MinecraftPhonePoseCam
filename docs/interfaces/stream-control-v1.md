# Stream Control v1（UDP 8092）

> 手机 → PC 推流主机。两端共享语义；**字段名禁止私改**。  
> 实现位：C4 `StreamControlSender` / B1 控制收包（或主机内嵌）。

## 报文

UTF-8 JSON，一包一对象。版本字段 `v`。

### 码率 / 帧率（已用）

```json
{ "v": 1, "t": 1710000000123, "bitrate": 12, "fps": 30 }
```

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `v` | int | — | 协议版本，当前 `1` |
| `t` | long | ms | 发送时间戳（可选但推荐） |
| `bitrate` | int | Mbps | 目标码率，建议 2–40 |
| `fps` | int | Hz | 编码帧率，建议 15–60 |

- 端口：发往 **主机 IPv4 : 8092**（与视频 8091 配对：`ctrl = video + 1` 的现行实现需在 HANDOFF 对齐；**规范默认写 8092**，若实现用 `port+1` 在 B1 HANDOFF 注明兼容）。

### 断线 / 心跳（预留，字段可选）

```json
{ "v": 1, "type": "PING", "t": 1710000000123 }
{ "v": 1, "type": "PONG", "t": 1710000000123 }
{ "v": 1, "type": "STOP" }
```

未实现前 App 可忽略；实现时不得改动 `bitrate`/`fps` 含义。

## 错误处理

- 主机无法解析 → 丢弃，不回错误包（UDP）
- App 侧记录 `errorCount`，UI 可显示，不崩溃

## 端口一致性备忘

历史代码：`StreamControlSender` 发往 `dataPort + 1`（视频 8091 → 控制 8092）。  
**规范目标**：控制固定 **8092**；视频 **8091**。实现应与本表一致；不一致只允许在 B1/C4 HANDOFF 写「legacy」并规划对齐。
